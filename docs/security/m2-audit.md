# M2 audit

## Environment and evidence scope

Read-only audit on 24 October 2026. Base commit:
`036bde95c74d517f80c17e6bf32e92d300e3b873`. Windows 11 Home 10.0.26300,
eight logical CPUs, approximately 31 GiB RAM, Docker Engine 29.9.2,
`desktop-linux` context; Ubuntu/WSL uses the same engine. Docker reports default
seccomp and cgroup namespaces. No Code Agent containers (including stopped ones),
Windows/Ubuntu application listeners or ngrok process were found. There is no
local `.env`; actual bot registration and token permissions remain UNVERIFIED.

Six FamilyFin containers are healthy/running: synthetic and restore API/web/Caddy
stacks. Only their Caddy services publish localhost 8090 and 8091 respectively.
Synthetic API storage is `familyfin-m1-synthetic_financial`; restore API storage is
`familyfin-m1-restore_financial`. No worker/test may mount either. Both API services
are non-privileged, read-only-root containers on private FamilyFin networks.
The active synthetic images use `candidate-combined-20261024` tags; tags alone do
not independently establish provenance from approved release `d14bd63`.

M0 still publishes localhost 8088. An unrelated Adminer occupies localhost 8080,
which conflicts with Code Agent's default Temporal UI port during future startup.
Tailscale Serve is tailnet-only HTTPS → localhost:8090. No Funnel public route was
shown. M2 must not repoint Serve or restart Adminer to resolve this conflict.

Metadata inspection includes image IDs, mount destinations/types/permissions,
network names, publication addresses and hashes of full container configuration;
raw environment values and application records were never emitted. Reproducible
preservation receipts are generated by `scripts/m2_preservation.ps1` under ignored
`artifacts/`. Do not confuse a metadata hash with a filesystem/data-integrity check.

Reviewed M0 `docs/results.md` and FamilyFin release documentation:
`windows-deployment`, `windows-security-assessment`, `windows-validation`,
`portable-backup`, `runtime-security`. Older pending-work notes do not override the
user's October 24 synthetic closeout. Existing exact-image findings, recovery and
production approvals remain outside M2.

## Findings

| ID / severity | Boundary, prerequisites and actual impact | Confidence / mitigation / remediation |
| --- | --- | --- |
| A01 HIGH | Internet → API: configured ngrok target `api:8000` would publish every API route when activated | Confirmed repository configuration; no running tunnel. Retarget restricted ingress and separate edge network |
| A02 HIGH | Telegram → task service: missing secret bypasses auth in baseline; any caller reaching this deployment could submit | Confirmed code; live exploitation not demonstrated. Require explicit enablement and valid secret |
| A03 HIGH | Telegram transport → human: valid-header deliveries accept arbitrary users/chats, channel posts and forwards | Confirmed code. Require numeric sender + private-chat IDs, reject ambiguous/senderless/forwarded input |
| A04 HIGH | LAN/tailnet → service: wildcard Compose publications include DB, Temporal/UI, API, dashboard, ngrok inspection and Phoenix | Confirmed config, not live listeners. Retain tooling ports on IPv4 loopback; independent LAN/IPv6 checks pending activation |
| A05 HIGH, architectural | Compromised trusted worker → shared daemon: socket provides unrelated volume/container and available host-mount authority | Confirmed mount and Docker design, no malicious daemon action performed. Child hardening does not solve it; dedicated VM recommended before sensitive coexistence |
| A06 MEDIUM | Child → provider auth: staged provider home/files are writable by child UID; child can alter task-local auth | Confirmed ownership/mount code; original source homes already read-only. Add immutable credential-file overlays, validate refresh before activation |
| A07 HIGH | Legacy/shell → execution boundary: baseline inherits root broker UID, lacks native privilege floor and uses default bridge for network-enabled tasks | Confirmed command construction; no breakout claimed. Non-root/capability/rootfs controls plus task-private proxy networking |
| A08 MEDIUM | Credential selection → worker: broad source auth-home binds expose unrelated files; explicit missing source silently falls back to another account directory | Confirmed Compose/bootstrap/startup code. Bind only required files and fail on explicitly selected missing credentials |
| A09 MEDIUM | Build context → image: `.env` excluded but variants/nested auth files can be copied by `COPY .` | Confirmed exclusion gap; no committed secret discovered or known leaked image asserted. Broaden exclusions, retain intended public CA certificate support |
| A10 MEDIUM | Ingress → memory: text limit occurs after unbounded JSON body parsing; malformed secret comparisons can raise encoding errors | Confirmed code. Bound streamed input before parsing, reject duplicate/non-ASCII headers before comparison |
| A11 MEDIUM | Diagnostics → secrets: ngrok captures headers/body by default and registration prints raw error responses | Confirmed configuration/code. Disable local inspection, suppress secret-bearing failure bodies and URL arguments |
| A12 OPEN REQUIREMENT | Private task → cloud: redaction does not prove local-only inference; existing cloud defaults intentional | Code inspection, no private task transmitted during audit. Document limitation; verify an explicit supported local route before local-only work |
| A13 MEDIUM | Legacy child → allowlisted local source: baseline source bind was writable even though it is outside the assigned clone | Confirmed conditional command-construction gap; no financial path mounted. Always mount local source remotes read-only; publication remains broker-owned |
| A14 MEDIUM | Read-only task → shell adapter: read-only requests were not forwarded into the container request; namespaced handles also lost their actual container name | Confirmed code gaps; no live mutation demonstrated. Pass request/constraint policy and node namespace through, preserve the name for reconnect/cleanup, and cover the API/Temporal/shell boundary and actual mount controls |
| A15 MEDIUM | Control-command failure → diagnostics: legacy container launch errors included argv that can contain scoped environment credentials | Confirmed conditional code path, no real credential leak observed. Emit only error category/errno or timeout and suppress credential-bearing chained exceptions |

## API authentication inventory

| Routes | Effective protection |
| --- | --- |
| `/health`, `/ready`, framework `/docs`, `/redoc`, `/openapi.json` | No operator authentication; restricted ingress blocks public access |
| `/auth/login` | API shared secret supplied to login; session-cookie creation, no separate login origin check |
| `/auth/logout`, `/auth/status` | Existing session/auth and origin behavior; public ingress blocks both |
| `/tasks` including create/scout/approval/cancel/replay/interactions | `require_any_valid_auth`: API header or dashboard JWT; cookie writes require CSRF/origin checks |
| `/sessions`, `/proposals`, `/knowledge-base`, `/system`, `/metrics` | Same router-level operator authentication; system diagnostics are not public |
| `/webhook` | Shared API header; not exposed through Telegram ingress |
| `/telegram/webhook` | Baseline optional secret only; M2 explicitly enabled, mandatory secret plus sender/chat policy |

Tests exercise synthetic unauthenticated/negative requests against the same API
code and a real proxy with a recording upstream. No public URL or live task API
was available for a real unauthenticated-request audit. Exact route inventory can
be obtained from `create_app().routes` without starting services.
